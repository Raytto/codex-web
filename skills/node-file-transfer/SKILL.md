# 节点文件互传

传输的发起、路由、状态和清理由 Codex Web 服务端统一管理。Worker 只执行服务器授权的读写。即使当前 Agent 在某台 Worker 上运行，也不要自行 SSH、启动文件服务器、上传会话附件或编写临时分片脚本完成中转。

## 发起

1. 明确源节点/文件、目标节点/含文件名的路径。默认复制，不删源，不覆盖已有目标；只在用户明确要求覆盖时传 `overwrite:true`。游戏等正在写入的文件先由相应节点停止写入并确认稳定。目标父目录必须已存在。
2. 调用 `pp_agent_transfer` 的 `nodes`，用返回的真实节点 ID；不能猜测节点 ID，不能混用不同实例的节点。节点不在线或未升级时明确报告，禁止悄悄回退旧附件链路。
3. 用 `create` 创建任务，固定保存 `idempotencyKey`；请求超时先按同一个键重试或查询列表，不能生成新键重复传输。输入示例：

```json
{
  "action": "create",
  "source": {"executorId": "从 nodes 返回值选择", "path": "源节点上的绝对文件路径"},
  "target": {"executorId": "从 nodes 返回值选择", "path": "目标节点上的绝对文件路径"},
  "idempotencyKey": "为本次意图创建并保留的稳定标识",
  "overwrite": false,
  "route": "auto"
}
```

`route:auto` 默认先直连，连接失败后由服务端选择加密内存中继；`relay` 只在用户明确要求或受控验收时指定。正文不进入服务器附件库。当前单文件上限 2 GiB，多个文件逐个建立任务；不为绕过限制自动拆成落盘分片。目录批次须列出清单和逐项状态，不承诺整目录原子替换。

## 查询与收尾

- `get` 传任务 `id`；`list` 查本账号最近任务。结果是服务端持久状态，独立于当前对话和模型上下文。
- 传输较长时记录任务 ID，使用当前可用的持久等待工具安排同会话续查并结束本回合，不循环 sleep 占用 Worker。
- `committed:true` 表示目标已提交；只有 `state:completed`、`outcome:success`、两端 `cleaned:true` 才能报告“完成且临时数据已清理”。`cleanup_pending` 必须如实说明，离线节点恢复后继续清理。
- 取消使用 `cancel`。已提交正式文件保留，不把取消扩展为删除目标；清理只处理传输服务自己的临时对象。
- 最终说明源/目标、文件数量与大小、实际直连或中继、校验和清理结果。不要把目标文件的本地路径作为网页附件链接再次上传；可交付小型文字回执。

## 没有动态工具时

在 Codex Web 发起的回合中运行随技能附带的脚本：

```sh
node scripts/transfer.mjs --request-file request.json
```

请求 JSON 与动态工具参数相同。脚本从当前回合的 `PPAGENT_AUTOMATION_*` 环境读取短期凭据，只访问本任务所属 Codex Web；不打印、不复制 token。脚本路径相对当前 SKILL.md 所在目录解析。不要从其他账号或另一实例借凭据。环境缺失时报告入口不可用，不自行签发管理员会话。
