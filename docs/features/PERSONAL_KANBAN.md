# 项目看板

个人设置 → 功能选择 → **项目看板**。沿用账号的显示选择，隐藏不会删除项目、资料或会话关联。

## 使用流程

卡片代表一个能结束的成果项目；工程仍负责执行目录，会话负责一段具体工作。看板按 **想法池 → 准备中 → 进行中 → 待验收 → 已完成** 展示。可跳过准备，验收不通过可退回修改；一次 Job 结束不会自动完成项目。

- 想法只需一句话。准备时补目标、完成标准、约束、决定、问题和下一步，可标记准备就绪。
- 开始推进时检查目标、完成标准、下一步和投入边界，展示跨看板在制数量。上限默认 3，可在「看板设置 → 推进提醒」按账号修改为 1–30；这是提醒，不限制机器任务并发。看板顶部不再常驻统计卡片。
- 等待记录对象/事项，暂停记录原因，两者保留当前阶段并可设置下次回顾日期。已启动的等待/暂停项目继续计入在制。
- 提交验收保存成果入口、检查依据与未验证项；成果页收录文件、链接、笔记。确认完成必须记录验收结论；退回修改可直接写返工下一步。
- 终止必须记录原因，单列在「已终止」页，与完成区分。完成和终止均可重新打开，历史结论保留在记录中。
- 归档只影响日常可见性。尚处于进行中/待验收的项目即使归档仍计入在制，跨看板「待我处理」可以找到并恢复。上述操作均不隐式取消会话、Job 或自动续跑。

「待我处理」聚合待验收、等待/暂停、到期回顾、缺少下一步及一周未回顾的项目；也可查看全部未结束项目。完成回顾保存下一步、回顾时间及可选的下一次日期。日期以亚洲/上海的日历日计算，只作界面提醒，不自动安排模型任务。

卡片顶部用带颜色圆点的阶段标签直接打开阶段菜单，列标题、标签与菜单颜色一致（灰 / 黄 / 蓝紫 / 橙 / 绿，终止为灰紫）。不再重复显示底部阶段选择框；空白说明与零资料/会话计数省略。电脑可以拖卡片或点击标签，需要结论的阶段会打开对应表单。工具栏保留阶段筛选、排序与视图切换；搜索统一使用侧栏入口，暂停仍在卡片和详情显示。筛选为空时可以直接恢复全部项目，列表视图按行展示。

手机按阶段纵向展示，阶段标签与菜单选项保留至少 44px 的触控高度，不压成五个窄列。看板与项目位置按账号保存在本机，刷新可回到原处，主动切换会话或隐藏功能会清除看板位置。

## 资料与会话

现有资料文件、来源、成果标记、主/参考会话关联、工程默认选择、语音记录与账号隔离保持有效。新会话继续先进入草稿；发送时固定主项目简报、生命周期状态与资料索引，不暗改已经接受或排队的输入。参考项目不自动带入背景。

原有领域退出主导航，不再要求用户归类。原来的分类笔记在「归档 → 原有分类笔记」可读，资料仍在项目资料页；没有删除已有内容。

## 数据与兼容

迁移 `2026093004 personal-kanban-lifecycle` 是事务内的增量迁移。`para_*` 表、API 路径、ID 和资源目录作为内部兼容标识保留，产品不再以 PARA 组织工作。

- 新 `workflow_stage` 约束包含 `idea/incubating/active/review/done/stopped`，API 的 `stage` 表示该字段；旧四态 `stage` 保留镜像（review → active，stopped → done），避免重建有外键的业务表。
- 原四阶段按原含义迁移，既有 done 不回退验收，也不推测 active 是否完成。旧历史的开工/结束时间保持未知；后续明确的生命周期操作记录 `started_at/ended_at/stage_changed_at`，不拿通用 `updated_at` 冒充开工时间。
- 等待、暂停原因、回顾日期/时间、投入边界、准备就绪、验收说明及结束结论有专用字段。版本检查与项目事件继续覆盖所有修改。
- `kanban_preferences` 按账号保存上限与 revision；统计按项目去重，跨同账号全部看板，包括归档中的在制项目。
- 升级前由部署者备份数据库与租户卷。旧程序回滚时四态镜像可读，但只能显示旧阶段语义；新字段和事件保留。旧程序写入阶段由兼容触发器同步；上线前的新 Job/排队快照原样保存。

## 验证入口

`tests/kanban.test.ts` 覆盖旧 schema 迁移/事务回滚/外键/历史快照、生命周期转移、结束结论、重开、归档在制、输入快照、账号权限/CSRF、设置冲突及重启持久化。`tests/browser/personal-kanban.mjs` 使用真实浏览器和独立测试数据，覆盖完整项目闭环、资料/会话草稿、冲突与断网恢复、刷新、窄屏和深色主题，最后清理测试数据并恢复设置。`tests/browser/personal-kanban-agent.mjs` 仅在显式设置 `CODEX_WEB_BROWSER_MODEL_PROBE=true` 的授权测试环境使用一个独立模型回合，验证阶段、验收说明和不可预测的附件内容；旧 `para-acceptance.mjs` 入口转接到新的场景。

真实模型、语音供应商和实际手机系统能力仍需各自的实际链路证据；Linux Chromium 的手机视口不等于真实 iOS Safari。
