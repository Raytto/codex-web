# November 2026 full capability update

This release adds PP Dot coordination/ledger/memory, scoped continuous voice, storage lifecycle and portable recovery modules, managed Codex memory extraction, recursive native-history archival, memory protection, Worker liveness, context capsule/navigation and progress fixes. Runtime identity and unlimited complete-workflow admission already shipped in the preceding release and remain shared core. Username/password login and the low-privilege base deployment remain intact.

Read [中文逐步配置](SETUP_GUIDE.zh-CN.md) or [English setup](SETUP_GUIDE.en.md) before enabling new integrations. Existing API memory extraction remains available; managed Codex is opt-in. Live voice is disabled until enabled plus endpoint/model/key-file are supplied. No private proxy, model default, account binding or storage data is included. The recorder also supports an explicitly configured OpenAI file-transcription provider; see [provider setup](VOICE_TRANSCRIPTION_PROVIDERS.md).

## Before upgrading

1. Preserve local edits. Record the current public commit, image tag and a consistent backup of `.env`, state and any separately managed keys/auth directories. Drain running tasks before taking a stopped-state copy; SQLite WAL and related files are part of the state.
2. Read [build and rollback](BUILD_AND_STORAGE.md), then build the reviewed `main` commit with `scripts/build-image.sh`. `runtime` stays the default; `documents` remains optional. No host npm install is required for the base path.
3. Recreate app, checking initialization, health and username/password login. Do not replace the public configuration adapter with upstream private deployment files.

## Data migrations and compatibility

New versioned tables cover Dot, conversation voice, persistent event sequence and storage catalogue; personal-memory run audits add provider/effort/runtime-verification fields. Existing conversations, passwords, account ownership, stored task choices and API-memory configuration are retained. Feature visibility does not delete underlying records.

Recursive cold archives use format v3 with thread lineage and file modes/ownership. v1/v2 archives remain readable. Unknown, conflicting or active native records block eviction; a metadata index is never a substitute for the original. The new chunk lifecycle stays disabled unless separately configured. Do not point two instances at the same state root, maintenance lock or cloud root. Keep old encryption keys and validated recovery points during migration.

The Worker retains its independent versioned-package protocol and explicit device credentials. Verify the exact bundled version/ref/commit, a real task, cancellation and reconnect before considering a physical-node upgrade accepted. Full workflow capacity `-1` does not change Worker capacity.

## Acceptance checklist

- Default and custom base paths: login/logout, nested routes, dynamic identity, skills, PDF/HTML reading, ordinary tenant task/file/restart checks.
- Missing configuration: voice calls unavailable; no memory extraction; no cloud archive or host authority implicitly activated.
- Configured paths: Dot owner/project scoping, idempotent task creation, correction/forgetting and real result references; same-conversation voice, interruption and takeover permissions; both memory providers.
- Persistence: wait/retry/complete-workflow ownership, job event replay, multi-engine handoff and no silent account switch.
- Storage: synthetic encryption/upload/download/restore checks, path traversal/ownership/active-writer rejection, SQLite consistency and an isolated recovery drill with integrity checks. Real cloud authorization/upload must be verified by the installer separately.
- Devices: desktop and mobile viewport checks; actual iOS microphone/audio interruptions and physical Worker execution are separate checks, not inferred from emulation.

If an acceptance check fails, retain the candidate and logs, avoid advancing the publication/recovery cursor, and restore the matching image plus pre-upgrade state if necessary. Do not use an old binary against a new schema without an explicit compatibility guarantee.


The final source includes stale Live playback/connection recovery, timestamped transcripts, real upload progress, deferred steering while transcription is pending, shared low-quota reset-credit controls, compact context menus and recording-start guards. These are implemented features; production cloud/physical-device acceptance must still be performed by each installer.
