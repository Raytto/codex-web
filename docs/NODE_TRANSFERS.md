# 节点文件传输

显式配置的宿主管理账号通过设置页“节点文件传输”、`pp_agent_transfer` 动态工具或 `node-file-transfer` 技能发起。Codex Web 服务端持久化任务、发放短期单次通道凭据、协调连接、重试和清理。Worker 和宿主桥只执行指定任务、角色与绝对路径；模型回合结束不影响任务。

## 数据路径

控制消息使用现有受认证 Worker / 宿主桥；正文使用独立 `<BASE_PATH>/api/node-transfers/connect` WSS 通道或 WebRTC DataChannel。ICE/STUN 尝试节点直连，双方确认后才发送正文；8 秒预算内不能直连则使用 Codex Web 的 WSS 内存中继。直连断开时服务端创建新 epoch，默认使用中继续传。当前没有独立 TURN 服务，也没有浏览器本地文件端点。

所有正文和文件清单均由端点使用 libsodium 临时密钥交换和 XChaCha20-Poly1305 secretstream 加密；每个 epoch 重建密钥，任务 ID 与 epoch 是认证附加数据。服务端通过已认证控制通道分发公钥，因此这是信任 Codex Web 协调端的端到端加密，不抵御控制端主动替换密钥。中继只转发加密帧，既不写文件，也不走会话附件、Worker outbox 或冷存储。

服务器保留任务元数据（节点、路径、大小、SHA-256、状态及清理回执）；不记录密钥、通道 token 或正文。WSS 逐帧上限、2 MiB 缓冲边界和端到端 1 MiB 确认限制内存占用。最多四个传输尝试，同一节点一次只参与一个任务。

## 文件生命周期

源端只读原文件。目标端在目标文件系统创建私有 `.ppa-transfer-<UUID>/payload`，每 1 MiB 同步文件并保存校验过的续传偏移。续传先验证已有前缀；源大小/哈希改变时失败，不拼接不同版本。完成后校验 SHA-256，再原子发布正式文件并删除暂存名称。不覆盖模式使用 hardlink + unlink；不支持硬链接的文件系统会安全失败，不回退复制覆盖。明确授权覆盖时用 rename，Windows 文件被占用可能拒绝。

默认不覆盖、不删除源文件。接收目录须已存在；仅支持普通文件和绝对路径，单文件上限 2 GiB。目录任务由技能建立多个文件任务，不保证整目录原子提交。临时文件绝不作为交付附件或冷存储对象。

任务总期限 24 小时；有传输进度后，未完成部分的续传租期为 10 分钟。在线端每分钟清理到期且不活跃的自身暂存对象；离线期间不能保证删除，重连/启动后补清理。取消不删除已经正式提交的目标文件。删除按自有路径和文件身份进行，遇到未知替换或额外文件停止并报告，绝不递归删除未知内容。

`committed=true` 只表示正式目标已提交；`state=completed` 且双方 `cleaned=true` 才表示成功并清理完毕。无法确认清理时保留 `cleanup_pending`，不可宣传为已清理。已提交但未回执的崩溃通过文件身份和哈希恢复。正常完成只留下原文件、正式目标和小型元数据；此机制不保证物理介质安全擦除，也不控制外部系统快照/备份。

## 权限与 API

仅 已配置的宿主管理账号可用，与其现有任意本机/远程文件权限一致。常规 API 使用会话和 CSRF；自动化 API 使用本实例当前 running Job 的短期 token，并核对对话所属账号。正文通道要求每次尝试的角色 token；每个角色只接一个连接。旧 epoch 被撤销，凭据不落库。

- `GET /api/transfers/nodes`：节点和能力。
- `POST /api/transfers`：source/target `{executorId,path}`，固定 `idempotencyKey`，可选 `overwrite=false`、`route=auto|relay`。
- `GET /api/transfers` / `GET /api/transfers/:id`：持久状态。
- `POST /api/transfers/:id/cancel`：取消与清理。
- 自动化路径为 `/api/automation/jobs/:jobId/transfers`，字段相同。

`skills/node-file-transfer` 是技能源码。宿主管理账号首次缺失时从该目录种入账号技能库，经现有账号技能机制同步到 Worker；已有自定义同名技能不覆盖。没有动态工具时使用附带 CLI，凭据只从本回合自动化环境读取。

## 发布与验收

Worker 包版本 1.20.0；运维人员应从已审查的公开提交构建并配置对应发布包，不能借用其他实例或仓库的同名标签；远端包包含纯 JS/WASM 依赖，无新增原生编译。宿主发布同步生产依赖，供宿主桥执行传输端点。旧 Worker 不具备传输能力，不自动回退附件中转。

自动化测试覆盖真实直连（中继字节为零）、加密中继、哈希与清理、接收进程和协调器重启、空文件、取消、幂等、不覆盖、部分文件损坏、原子发布崩溃恢复、未知文件保留、租期清理以及 HTTP/WS 权限。生产须核对 Worker 实际重连版本、服务器↔节点↔节点的独立测试文件、任务状态及残留，并用临时登录会话验收界面。不能以开发机直连测试替代真实 NAT 网络结果。

## 公开部署

默认 Compose 没有宿主 socket 或主机文件系统挂载，不能作为宿主文件端点。只有显式配置 `CODEX_WEB_HOST_SOCKET_PATH` 的宿主端点才会报告可用能力；普通租户无传输管理权限。`PUBLIC_BASE_URL` 必须包含公开入口的 HTTPS 地址及子路径（例如 `https://example.com/codex-web`），宿主桥和 Worker 必须使用同一入口。反向代理模板已包含独立 WSS 升级路由和 2 GiB 请求体上限；不要把示例配置当作已启用能力。
