# 弹窗字号与布局规范

账号管理弹窗是本规范的参考实现。新增或改造管理、设置、表单弹窗时，使用 `src/dialog-tokens.css` 的语义变量，并在容器添加 `ui-dialog`。规范适用于桌面与手机；手机空间不足时优先换行、堆叠、滚动，保留字号。

## 字号层级

像素值按浏览器默认根字号 16px 换算；实现使用 rem，尊重浏览器字体设置。

| 用途 | 变量 | 默认字号 | 字重 / 行高 | 使用原则 |
| --- | --- | --- | --- | --- |
| 弹窗标题 | `--dialog-font-title` | 20px | 650 / 1.4 | 一个弹窗一个主标题；用 `dialog-title` |
| 分区标题、账号名称 | `--dialog-font-heading` | 16px | 650 / 1.5 | 用 `dialog-section-heading`；按语义使用 h3/h4 |
| 正文、主要数据 | `--dialog-font-body` | 15px | 400（数据 650）/ 1.6 | 主要信息清晰可读，避免随意放大数字 |
| 表单标签、描述、时间、邮箱 | `--dialog-font-secondary` | 14px | 400（标签 600）/ 1.6 | 用 `dialog-description`；重要时间不放进更小字号 |
| 所有文字按钮、操作链接 | `--dialog-font-control` | 14px | 600 / 1.4 | 主次操作字号一致，以颜色、边框区分 |
| 短状态标签、计数 | `--dialog-font-caption` | 13px | 600 / 1.5 | 最小字号；不用于正文、日期或长说明 |
| 输入框、下拉选择、文本域 | `--dialog-font-input` | 16px | 400 / 1.5 | 桌面和手机一致；手机不再另设小字 |

设备验证码可用 20px 等宽字体，它是需要识别和复制的数据。其余场景不要为每个组件新增字号。`ui-dialog` 为按钮及表单控件提供基线；子组件不得通过继承更大的父字号或另写 8–12px 绕开规范。

## 操作与状态

- 同一操作组只突出一个主动作。主次按钮均为 14px，不靠放大文字区分重要性。
- 按钮、图标按钮和输入控件至少 44px 高；纯图标按钮至少 44 × 44px。使用 `min-height` 配合内边距，长文案可自然增高。
- 普通操作图标 16–18px，标题及身份图标 20px。图标不挤压文字；图标按钮提供 `aria-label`。
- 状态标签不伪装成按钮。当前账号通过绿色文字标签和侧边强调线表示，不再显示满宽禁用主按钮。
- 删除为独立次级危险操作。刷新仅刷新数据；使用重置卡保留原有确认流程、忙碌禁用与幂等逻辑。
- 保留键盘焦点描边。成功、失败、加载、空列表均用正常字号表达。

## 间距与响应式

- 采用 4px 步进：信息内 4–8px，操作间 8px，相关组间 12–16px，分区间 24px。
- 桌面弹窗内边距 24px；手机 16px；卡片 14–16px。圆角：控件 10px、卡片 14px、弹窗 20px。
- 账号页桌面最大宽度 780px；小于等于 720px 改为底部弹层，最大高度 94dvh。固定头部，内部滚动，底部包含安全区。
- 手机上标题和操作组分行；操作组可换行；头像只占身份行，额度和重置卡信息使用卡片完整宽度。
- 账号名称、邮箱、错误说明允许换行。额度与重置时间采用带标签的数据组；时间不强制不换行，不裁掉关键值。
- 支持 320px 窄屏、390px 手机、平板和桌面。放大文字时允许弹层变高、内容滚动，不用固定高度或省略号掩盖信息。

## 明暗主题

正文使用 `--ink`，说明使用 `--dialog-text-secondary`，两种主题分别定义辅助文字颜色。辅助文字靠适度色差建立层级，避免同时极小、浅灰、低透明度。

主按钮背景用 `--indigo`，文字用 `--dialog-primary-ink`：浅色主题白字，深色主题深色字。状态颜色同时配合文字；禁用状态保留语义和 `disabled` 行为。

## 复用方式

```tsx
<section className="example-dialog ui-dialog" role="dialog" aria-modal="true" aria-labelledby="example-title">
  <h2 id="example-title" className="dialog-title">管理设置</h2>
  <p className="dialog-description">说明这个弹窗管理什么。</p>
  <h3 className="dialog-section-heading">分区名称</h3>
  <label>名称<input /></label>
  <button type="button">保存设置</button>
</section>
```

容器仍需实现自己的位置、滚动和关闭逻辑。标签使用 secondary token；主次按钮各自补充边框、颜色和内边距。字号引用相应用途的 token。修改公共 token 前检查所有已采用的弹窗，避免为某个局部布局压缩公共字号。

## 验收

在真实浏览器检查 320、390、768、1440px 宽度及明暗主题，并检查长账号名、长邮箱、无数据、加载、刷新失败/恢复、新增登录表单、禁用操作。检查无水平溢出、文字没有裁切、文本按钮字号一致且高度至少 44px；另以根字号放大到 200% 检查重排。

本地用合成数据覆盖状态，在独立测试部署使用普通用户名/密码登录 Codex Web，验证账号读取、机器切换、手动刷新和表单开合。不得为验证样式消费真实重置卡、切换活动账号或删除用户凭据。手机视口自动化不代表真机 iOS Safari 已验收。

此轮先迁移账号管理（含新增账号流程）；其他现有弹窗在后续改造时逐一应用并复查布局。
