# Upgrade: multi-engine sessions and remote presentations

Back up your own persistent state using your established recovery policy. Pull `main`, review `.env.example`, build the default `runtime` image using `scripts/build-image.sh`, then restart your existing Compose project with the same state roots. Do not replace tenant data, shared authentication policy or account credentials with another installation's files. `documents` remains optional.

Two additive migrations create engine/session binding tables and the durable Codex automatic-reset-use log. Existing business rows are retained. Rollback of application code does not restore a database; rehearse compatibility on an online SQLite backup before upgrading important state.

Worker 1.21.5 includes managed remote HTML declarations, engine-account support, node-specific defaults and expiring-credit handling. Upgrade supported nodes using the existing managed updater; a server change alone does not update a remote computer. Antigravity CLI installation remains an explicit optional account action. Configure the two optional Gemini naming variables only when desired; empty values keep that naming engine disabled.

Voice, memory and model-provider configuration remain optional and installation-specific. No new provider endpoint, login state or private model catalog is included. Username/password login, `/codex-web`, container tenant isolation, empty host configuration and absence of a Docker socket mount remain the default boundaries.

Sanitize-html, Vite and affected compatible transitive packages were updated to resolve current audit findings. Review dependency locks with the release; no optional document package became a default dependency. Source/tests/docs grow with the shipped features; dated older installation measurements are not new release measurements.
