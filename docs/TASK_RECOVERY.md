# 中断交接与现场核对

## 恢复契约

容量退避、主动取消、执行失败和服务重启中断都会从已有任务信息生成有界交接记录，不需要再调用模型。记录包含原请求节选、连续中断前的原目标、thread 与工程/执行器、输入是否接收、阶段反馈、计划标记、关键文件、最近操作标签/命令节选和错误原因。它不是文件快照，也不能证明操作已经完成。

`job_recovery_checkpoints` 每个 Job 一条，容量重试更新同一条记录，成为 cancelled/failed/interrupted 后仍保留；删除 Job 时通过外键级联清理。迁移 `2026092301` 只新增独立表，不改变旧字段与状态枚举，旧版本回滚可忽略该表。保存发生在终态 trigger 清除 attempt 元数据、协调器回收 runtime 之前。服务启动恢复也先保存再标记中断。

下一轮沿用原 Codex thread，并把交接记录和统一核对要求放入原有文本输入，因此 host、tenant、Remote Worker 都生效，已有 Worker 无须新增协议字段或升级。恢复上下文由同会话、同 thread、Job 顺序确定，取代旧“最近一条 assistant 恰好是停止摘要”的判断，不受 observer 阶段消息插入影响。可见的停止摘要仍保留，但不会绕过 thread 边界独立注入模型。

自动容量续接不重发原始用户要求、图片和已接收的个人背景；交接记录保留原要求，但同 Job 的投递省略这段重复目标。对于发布前已经处于容量 queued 的任务，首次续接从 attempt 与事件补建交接记录；历史已中断任务也可按需从日志补建。

## 模型收到的核对要求

1. 以当前用户要求为准；换题时不擅自继续旧目标。
2. 核对目标、约束、剩余项，只读检查本任务相关的文件、Git 改动、产物、验证记录和必要的进程状态。
3. 区分已验证完成、已改未验证、未执行和结果未知；最后命令与外部副作用必须核对，避免重复提交、部署、发送或覆盖修改。
4. 旧临时路径可能失效，需要定位持久原件或安全重建。
5. 核对后先向用户简短同步状态、差异与下一步，然后在已有授权内继续；只在关键缺失或无法安全决定时请求补充。

这是模型收到的明确执行要求，不是平台声称已完成工程检查的门禁。平台不自动读取远端整个工程，不把计划中的 completed 标记或 file 事件当作独立验收结果。

记录最多选取最近 200 条相关过程事件，保留 4 条阶段反馈、12 项计划、12 个文件和 3 项操作；原请求节选约 2400 字符，较长内容明确标注截断。完整已接收事件仍留在原 `job_events`，不会被摘要替换。后续成功完成的 Job 结束旧交接的自动投递；失败的“继续”会保留先前目标以免退化成只有“继续”二字。跨 conversation 或已换 thread 不投递旧记录。

## 取消与队列

取消摘要以“是否存在执行/输入接收历史”判断，覆盖容量等待中的 queued Job；普通尚未执行的排队任务仍不生成执行摘要。会话停止与单 Job 停止都使用同一判断，摘要写入有事件标记以避免重复。

停止不暂停或删除 `pending_prompts`，本次没有改变待发队列语义。项目已落盘文件和已登记交付物不因停止回滚；runtime 内未持久保存的原始文件不由交接记录代替保存。

## 报错时序与日志

- 模型报错和退避继续以独立 `progress/error`、`progress/retry` 事件写入 `job_events`。如果执行器直接抛异常而没有发出 error 进度，协调器补一条；同次尝试已报告相同错误时不再补写。
- 前端同 Job 重放按 seq 去重；相邻但 seq 不同、文字相同的错误或重试仍分别显示，不能用文字签名把两次错误合并。
- 当前实时窗口保持最近 50 条事件并额外保留最近 5 条过期阶段反馈；超出窗口的错误可能不再显示，但持久日志仍在，可经原 Job 的鉴权 SSE 重放取得。结束后实时卡片收起、新 Job 使用自己的窗口，这不删除旧 Job 日志。
- Remote observer 导入会剥离内部恢复封装，并识别带封装的容量续接，避免额外产生伪用户消息和暴露交接内容。

## 验证入口
