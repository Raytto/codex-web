# Upgrade checks: voice, execution ownership and lean builds

This update is additive. Back up this installation's SQLite and private configuration using your normal verified backup procedure; keep the previous immutable application image. Do not replace business state or copy another installation's credentials.

## User-visible behavior

- Attachment-only sends are accepted; a completely empty send still fails. Pending attachment edits survive reload, preserve files after a rejected edit and run once.
- Continuous project voice derives dialogue length from actual turns. Interrupting playback preserves the current connection and turn context; incompatible older voice clients receive an explicit refresh response. Refresh all open browser tabs after upgrading.
- Draft ownership and chat scroll position remain stable during background observer updates. Controlled Worker turns and acknowledged steering use durable identity; genuine desktop inputs and attachment-bearing ambiguous copies remain visible.
- Gemini progress exposes stages and concrete operations. Auxiliary naming uses the configured Codex title path independently of the task engine. CLI authentication and any optional provider credentials still belong to the local installation.
- Short SQLite attempts and bounded retries protect metadata callbacks. No user instruction, tool operation or external command is automatically replayed by a metadata retry. Workflow recovery still requires verified executor exit.
- Optional cold storage uses short access-monitor/event transactions, bounded chunk layout and portable recovery proof before reclaiming eligible local copies. The catalogue publisher stores the verified descriptor proof needed by these gates. Existing grace periods, references, leases and permissions remain enforced. This update does not enable storage or change cloud ownership.

See [remote turn ownership](REMOTE_CONTROLLED_TURNS.md), [SQLite recovery](SQLITE_CONTENTION_RECOVERY.md), [voice providers](VOICE_TRANSCRIPTION_PROVIDERS.md), [workflow admission](COMPLETE_WORKFLOWS.md) and [storage lifecycle](STORAGE_LIFECYCLE.md).

## Update this installation

Preserve local edits before updating; choose a reviewed main commit. In the repository's Bash terminal:

```bash
git fetch origin main
git merge --ff-only origin/main
CODEX_WEB_VERIFY_BUILD=1 ./scripts/build-image.sh
sudo docker compose up -d --no-build
sudo docker compose ps
```

Keep the existing private environment file and state mounts. If you use a custom image tag, build and restart with the same `CODEX_WEB_IMAGE`. Initial state ownership is handled by the existing init-state service. The default remains runtime; documents is opt-in. The helper builds a Git archive with a dedicated bounded builder and removes its own cache. Compilation is shared between the optional verification stage and runtime stage; Worker inputs have separate dependency stages. No host npm installation or retained test image is required for a normal install.

## Verification and rollback

Check password login, original conversations, attachment-only submit/edit/restore, narrow-screen scrolling and a real configured model/tool task. If voice is enabled, test a short recording plus a continuous call with an interruption and browser refresh. Synthetic tests do not prove paid API access, real microphones, Windows nodes or iOS behavior.

Check SQLite integrity/foreign keys and original business IDs after migration. Remote-import reconciliation retains audited internal rows instead of deleting canonical messages; a code rollback does not undo those data repairs. Review exact audit rows before any scoped recovery. For rollback, restore the previous image and its compatible configuration using your normal controller; do not overwrite the active database with an old backup to roll back code.
